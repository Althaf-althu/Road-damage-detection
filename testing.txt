3. PROBLEMS IDENTIFIED DURING TESTING & SOLUTIONS PROVIDED
--------------------------------------------------------------------------------

PROBLEM 1: FastAPI Server Startup Crash (Unable to connect to backend server http://localhost:8000)
- Symptom: Uvicorn container crashed on startup; frontend displayed "Unable to connect to backend server (http://localhost:8000)".
- Root Cause: In `backend/app/api/complaints.py`, `current_user: Optional[User] = None` lacked FastAPI's `Depends()` dependency wrapper. FastAPI attempted to inspect the SQLAlchemy ORM `User` class as a Pydantic request body, throwing `fastapi.exceptions.FastAPIError: Invalid args for response field!`.
- Solution:
  1. Defined `oauth2_scheme_optional = OAuth2PasswordBearer(..., auto_error=False)` and created `get_optional_user()` dependency in `backend/app/services/auth_service.py`.
  2. Updated parameter to `current_user: Optional[User] = Depends(get_optional_user)` in `backend/app/api/complaints.py`.

PROBLEM 2: Passlib & Modern Bcrypt 4.1+ Version Incompatibility
- Symptom: `ValueError: password cannot be longer than 72 bytes` during backend lifespan initialization; admin user was not seeded into PostgreSQL.
- Root Cause: `passlib 1.7.4` runs an internal version detection probe passing a 73-byte dummy test password to `_bcrypt.hashpw`. In `bcrypt >= 4.1.0`, `bcrypt.__about__.__version__` was deprecated and bcrypt raises a strict `ValueError` on passwords >72 bytes. This prevented the startup lifespan event from creating the admin account.
- Solution:
  1. Replaced `passlib.context.CryptContext` with direct native `bcrypt` calls (`bcrypt.hashpw` and `bcrypt.checkpw`) in `backend/app/services/auth_service.py`.
  2. Added `bcrypt==4.0.1` explicitly to `backend/requirements.txt`.
  3. Verified automated idempotent admin creation directly from `.env` on container start.

PROBLEM 3: Celery Worker Crash (Kombu Transport Version Mismatch)
- Symptom: `road_damage_worker` container was in a restart loop (`Restarting (1)`).
- Root Cause: `kombu.exceptions.VersionMismatch: Redis transport requires redis-py versions 6.1.0 or later. You have 5.0.4`.
- Solution:
  1. Upgraded `redis` requirement from `redis==5.0.4` to `redis>=6.1.0` in `backend/requirements.txt`.
  2. Rebuilt the worker container.

PROBLEM 4: OpenCV Missing Library in ML Pipeline Container
- Symptom: `road_damage_ml` container failed to start with `ImportError: libGL.so.1: cannot open shared object file: No such file or directory`.
- Root Cause: Debian slim Python image lacks native OpenGL libraries required by `opencv-python`.
- Solution:
  1. Added `libgl1` to `apt-get install -y --no-install-recommends` in `ml_pipeline/Dockerfile`.
  2. Rebuilt `ml_pipeline` container.

PROBLEM 5: Empty Road Network Database Preventing Snapping & Map Vectors
- Symptom: When submitting complaints on a fresh database, complaints were assigned to "Unassigned Network Location" with 0 polylines rendered on the vector map because `road_segments` had 0 rows.
- Root Cause: Road network population originally depended exclusively on querying the Overpass OSM API for 180,000+ statewide ways, which is slow and requires external internet during setup.
- Solution:
  1. Created `backend/scripts/seed_sample_roads.py` defining core regional arterial corridors (NH 766 Wayanad Ghat Road, NH 66 Kozhikode Bypass, MG Road Ernakulam, NH 66 Kazhakoottam Bypass).
  2. Embedded automatic startup corridor seeding into `lifespan` in `backend/app/main.py` so fresh container deployments immediately have vector snapping and colorful road polylines.

PROBLEM 6: Header Congestion & Text Clipping on Admin Dashboard
- Symptom: The heading "Road Maintenance Command Center" wrapped into two lines, with the top half sliced off by the browser toolbar; the layout looked cramped and cluttered on laptop resolutions.
- Root Cause:
  1. A duplicate middle status legend pill was competing for horizontal space on medium viewports.
  2. The header container had a fixed height `h-16` (64px) which overflowed when text wrapped into 4 lines.
- Solution:
  1. Expanded header container to flexible `min-h-[4.25rem] py-2.5` to provide comfortable top and bottom padding.
  2. Added `whitespace-nowrap` and `shrink-0` to the brand title and division subtitle so text remains on single lines without wrapping.
  3. Removed redundant duplicate status legend from top bar (already prominently visible in KPI cards and map legend right below).

PROBLEM 7: Low Contrast on Cards Against Scenic Photographic Backdrop
- Symptom: Text and secondary metrics on the admin war room cards blurred out and became difficult to read against the bright parts of the photographic backdrop.
- Root Cause: Cards were configured with low-opacity styling (`bg-slate-800/40`, `bg-red-950/20`, etc.) and muted text colors (`text-slate-500`, `text-red-500/80`).
- Solution:
  1. Upgraded card backgrounds to high-density slate (`bg-slate-900/90 border border-slate-700/80 backdrop-blur-md shadow-2xl`).
  2. Brightened all metrics and sublabels to high-contrast colors (`text-slate-200`, `text-red-200`, `text-amber-200`, `text-emerald-200`).
  3. Applied an administrative dark backdrop overlay (`from-slate-950/85 via-slate-900/80 to-slate-950/90`) to maintain map and telemetry legibility while keeping the scenic background visible.

PROBLEM 8: Password Visibility Toggle Missing on Authentication Forms
- Symptom: Users could not inspect typed passwords on login and registration pages.
- Solution:
  1. Added stateful `showPassword` toggle button with `Eye` and `EyeOff` icons from `lucide-react`.
  2. Applied to Admin Authority Login, Citizen Sign In, and Citizen Registration forms.
